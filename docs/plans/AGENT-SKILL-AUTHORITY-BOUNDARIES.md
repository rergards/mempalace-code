## Design Notes

- Treat the current backlog contract as the exact behavioral source. Keep all six acceptance IDs stable and make every negative case observable through focused contract-test output.
- In the shared state procedure, read the selected state file and Git state before any write. For Autopilot state, require `autopilot doctor --json` before `autopilot status`; evaluate `phase_write_allowed` only inside the owning provider and `safe_to_edit` only for the operator. Active, blocked, resumable, stale, unknown, or contradictory ownership preserves the file and stops with the failed predicate plus `autopilot doctor --json` as recovery.
- Keep state creation idempotent: initialize only when the state path is absent and the relevant live owner allows that exact write. A valid existing file is resumed; malformed or mismatched evidence is retained for diagnosis rather than overwritten or cleared.
- In the checkpoint, order admission as repository root and Git directory, current status and intended paths, live owner, exact staged content and message, then current authority. Model staging, commit, and amend as distinct single-attempt mutations; inspect index and `HEAD` after ambiguous outcomes before requesting fresh authority.
- In ship, require literal repository, remote, full destination ref, and 40-hex local SHA. Normalize supported remote URLs to owner/repository identity. For GitHub, compare that identity with `gh repo view --json nameWithOwner,isPrivate`; unknown identity or visibility stops before any authority request. Re-read owner and remote SHA immediately before an exact ordinary push.
- Route any public target or release intent directly to `.claude/skills/release/SKILL.md` and perform no ship push. Do not duplicate release admission, tag, branch promotion, or publication instructions.
- Planning and hardening invocation authorizes inspection, triage, chat output, and ignored local evidence only. Source edits, tracked plan/report writes, backlog mutation, staging, commit, amend, ordinary push, and publication each need fresh authority bound to their exact paths, command/message, repository, target, SHA, and observed state.
- Bind provider-failure evidence to run, attempt, provider, model, phase, and freshness. Repeated or partial invocation reads existing evidence and post-state first, never repeats completed work, and asks only for the one remaining authorized action.
- Add `tests/test_agent_skill_authority_contract.py` because the existing `tests/test_release_skill_contract.py` owns only the public release procedure. Reuse its bounded `_section` style while keeping assertions local to the exact owning section and adding order/absence checks; avoid generic whole-document phrase checks.
- After the focused test file changes metrics, run `python scripts/quality_scorecard.py --write` once and retain only `docs/quality/scorecard.md` and `docs/quality/scorecard.json`. Do not hand-edit generated metrics or change the generator.
- Verification commands run from the repository root. `pyproject.toml` declares `tests/` as the pytest path and excludes network/slow tests by default; `scripts/quality_scorecard.py` and `.claude/skills/verify/INSTRUCTIONS.md` identify `python scripts/quality_scorecard.py --check` as the canonical freshness check.
