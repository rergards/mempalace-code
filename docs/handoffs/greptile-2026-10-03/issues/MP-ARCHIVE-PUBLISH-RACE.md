## Проблема

Функция обещает публикацию без замены существующего файла. Если os.link возвращает OSError, fallback проверяет os.path.lexists(out_path), затем вызывает os.replace(tmp_path, out_path). Между проверкой и заменой другой процесс может создать файл по тому же пути. os.replace заменяет его без ошибки. Lease одного palace не защищает этот путь от внешнего writer или операции другого palace.

## Доказательство

Реальная функция извлечена через AST из проверенного source и исполнена с обычным os.replace. В тесте os.link возвращает EOPNOTSUPP. Проверка lexists видит отсутствие файла; сразу после проверки создаётся конкурирующий архив. По завершении его байты заменены новым архивом. Использованы только временные синтетические файлы.

Воспроизведение на текущем коде:

```sh
python3 <audit-checks>/mempalace_archive_publish_race.py --source <audit-source>
```

Результат: exit 1, overwritten=true, competitor_preserved=false. SHA-256 backup.py: e02bac542d81fc8ce227350d8f7aba0737d730572ff8d81833d9e32bc62e5917.

Этот скрипт доказывает текущую гонку. После изменения владельца exit 2 означает, что прежняя точка инъекции больше не достигнута; это требует новой проверки исправленного пути.

## Критерии исправления

- При конкурентном появлении out_path сохранить байты существующего архива и сообщить конфликт.
- При отказе hard link сохранить эту гарантию. Если платформа не даёт безопасного примитива публикации, завершить операцию с понятной ошибкой; совместимость такого отказа проверить против текущего контракта backup.
- Сохранить обычную успешную публикацию, отказ при уже существующем архиве, обработку временного файла и текущие правила retention.
- Проверить конкурентный сценарий на фактическом владельце и положительные контроли на временных файлах.
